# ファイル構成と命名規則

長研究室ホームページの共同開発で使用する、**ファイルの配置場所・名前・担当範囲の共通ルール**です。全員が作業前に読み、AIにも参照させてください。

> **基本方針**：HTMLはページ単位、CSSは共通＋ページ専用、JavaScriptは共通＋必要なページ専用、画像はページ別に管理します。使用技術はHTML / CSS / JavaScriptとし、既存の構成を優先します。

## 2. 担当者と主な編集対象

| 担当 | ページ | 主なHTML | 主な専用CSS |
| --- | --- | --- | --- |
| A（リーダー） | HOME、ゼミ一覧、VRゼミ、共通部分、教員個人紹介（要確認） | `index.html`, `seminar/index.html`, `seminar/vr.html`, `professor.html`（要確認） | `home.css`, `seminar.css`, `vr.css`, `professor.css`（要確認） |
| B | 研究室紹介、モーションシャープニングゼミ | `about.html`, `seminar/m-sharp.html` | `about.css`, `m-sharp.css` |
| C | デザインゼミ、アクセス、進路 | `seminar/design.html`, `access.html`, `career.html` | `design.css`, `access.css`, `career.css` |
| D | モーションゼミ、イベント | `seminar/motion.html`, `events.html` | `motion.css`, `events.css` |
| E | メンバー、論文・研究業績、配属希望者向け | `members.html`, `papers.html`, `join.html` | `members.css`, `papers.css`, `join.css` |

- `css/common.css`、`js/common.js`、共通ヘッダー・フッター・ナビゲーション、`docs/design-guide.md` はAが管理します。
- `css/seminar.css` はゼミページ共通のためAが管理します。B・C・Dが変更を希望する場合はAに相談してください。
- 他担当のページ・画像・CSS/JSを無断で変更しないでください。

## 3. ファイル命名規則

1. **ファイル名とフォルダ名は英小文字・数字・ハイフン（`-`）を基本**とします。空白、日本語、全角文字は新規のWeb公開用ファイル名に使用しません（既存の日本語名の設計資料はそのまま維持します）。
2. **HTML**：上記の決められた名前を使用します。ゼミ紹介ページは `seminar/` の下に置きます。
3. **CSS**：全ページ共通は `css/common.css`、ゼミ共通は `css/seminar.css`、各ページ専用は `css/ページ名.css` とします。
4. **JavaScript**：全ページ共通は `js/common.js`。ページ固有の機能が必要なときのみ `js/ページ名.js` を追加します。新規ファイル追加前にAへ相談してください。
5. **画像**：`images/担当ページ/` に置きます。ゼミ画像は `images/seminar/ゼミ名/` に置きます。画像名は用途が分かるもの（例：`vr-experiment-01.webp`）とします。
6. **ページの増設・改名**：ファイル名や配置を独断で変えず、Aに相談して決定します。

## 4. HTMLからの読み込み例

### ルート直下のページ（例：`about.html`）

```html
<link rel="stylesheet" href="css/common.css">
<link rel="stylesheet" href="css/about.css">
<script src="js/common.js" defer></script>
<img src="images/about/lab-room.webp" alt="研究室の活動風景">
```

### `seminar/` 配下のページ（例：`seminar/vr.html`）

```html
<link rel="stylesheet" href="../css/common.css">
<link rel="stylesheet" href="../css/seminar.css">
<link rel="stylesheet" href="../css/vr.css">
<script src="../js/common.js" defer></script>
<img src="../images/seminar/vr/vr-experiment-01.webp" alt="VRゼミの実験画面">
```

`../` は**1階層上のフォルダ**を指します。実際に存在する画像ファイル名に合わせて指定してください。

## 5. 共通デザイン・実装のルール

- 実装前に `index.html`、`css/common.css`、`docs/design-guide.md` を確認し、HOMEで採用したデザインを基準にしてください。未作成ならAに確認し、独自の共通デザインを作らないでください。
- 共通ヘッダー・フッターはAが提供する仕様・ひな形に合わせてください。単純な静的HTMLでは各ページに共通マークアップを配置することがありますが、デザイン・構造を勝手に変更しないでください。
- ページ専用CSSのクラスには、`about-`、`vr-`、`design-` などの接頭辞を付けてください。ページ専用CSSから `body`、`header`、`footer` などの全体要素を無条件に変更しないでください。
- ゼミページは見出し順、カード、写真配置を共通化します。`seminar.css` の変更はAと調整します。
- 写真・動画・研究内容・人物情報・業績など、未確認の事実は創作せず `[要確認]` と明記してください。公開許可を確認してください。
- PC・スマートフォン表示、画像、リンクを確認してください。実行していないテストを「確認済み」と記載しないでください。

## 6. GitHubでの作業ルール

1. 最新の `main` を取得します。
2. 担当ページごとの `feature/...` ブランチを作ります。
3. **担当ファイルだけ**を追加・変更します。
4. `git status` と `git diff` で変更内容を確認します。
5. コミット・プッシュ後、PRを作成してAにレビューを依頼します。
6. Aが共通デザイン、リンク、スマホ表示、競合を確認してマージします。

**注意**：Gitは空フォルダを管理しません。画像フォルダは画像を追加するときに作れば十分です。事前に共有する必要がある場合のみ `.gitkeep` を置いてください。

## 7. AIへの依頼時の確認事項

AIには必ずこの文書を読ませ、**作業開始前に「新規作成・変更予定ファイルの一覧と理由」を提示**させてください。許可していないファイルの変更、ファイル名の独自変更、新規フレームワーク・外部ライブラリの導入は禁止です。必要なら事前にAへ相談してください。
