# HOME・共通デザイン実装ガイド（初期案）

## 対象と意図

このセットは、研究室ホームページの **HOMEと共通スタイルのひな形** です。デザイン案をリーダーとメンバーで評価するための初期版であり、最終デザインとして確定したものではありません。

**作成ファイル**

- `index.html` — HOMEのHTML。ヘッダー、フッター、研究テーマへの導線、研究室の日常（写真枠）、配属希望者向け導線
- `css/common.css` — 共通の色・フォント・余白・ヘッダー・フッター・ボタン・セクション見出し
- `css/home.css` — HOME専用のレイアウト・装飾
- `js/common.js` — スマートフォンのメニュー開閉と、未作成ページへのリンク案内
- `docs/design-foundation-guide.md` — このガイド

ゼミ一覧や各ゼミのHTMLは **作成していません**。次のゼミ実習で作成する余地を残しています。

## デザイン方針

- キャッチコピー：**見え方が変わると、世界が変わる。**（既存要件定義書）
- 基本色：濃紺 `#101928`、白 `#ffffff`、淡い背景 `#f3f7fa`
- アクセント：青 `#2758c6`、ミント `#9df0df`
- 字体：OS標準の日本語ゴシック体（外部フォント不要）
- 一般カード：角丸16px。最大コンテンツ幅1200px
- デザイン：余白・読みやすさを保ちつつ、HOME冒頭で視覚をモチーフにしたCSS球体グラフィックを使用
- 画像素材：未使用。必要な写真位置には**明確な仮枠**を置いている
- モーション：`prefers-reduced-motion` を尊重する

## 他メンバーが新しいページを作るとき

1. 各HTMLの `<head>` で `css/common.css` を読み込み、その下にページ専用CSSを読み込む。
2. ヘッダーとフッターは `index.html` の構造を参照して統一する。*現段階ではHTMLの共通化機構を入れず、各ページに同じマークアップを使う暫定方式*。
3. ページ専用CSSのクラスには `about-`、`design-`、`motion-` などの接頭辞を付ける。
4. ボタンやタイトルには `.button`、`.section-title`、`.eyebrow`、`.text-link`、`.container` を再利用する。
5. スマホのメニューには、`data-menu-toggle`、`id="site-nav"`、`js/common.js` が必要。
6. `seminar/` の下のページからは `../css/common.css` や `../js/common.js` のように相対パスを修正する。
7. 変更したい共通要素があればリーダーに相談する。共通CSSやJSを各担当者が個別に編集しない。

## 未作成ページリンクの扱い

HOMEには、設計書に沿って他ページへのリンクを掲載しています。しかしリンク先のHTMLはまだありません。初期案では、これらのリンクに `data-planned` を付けてクリック時に「制作予定」の案内を表示します。**担当ページができたら、リンクの `data-planned` を削除してください。** これにより通常のページ遷移が動くようになります。利用者向け公開までに残っていないか確認が必要です。

## 掲載内容についての注意

- ページ冒頭の `VISUAL LAB` は仮ロゴ・仮称です。正式な研究室名を確認して差し替えてください。
- HOMEの紹介文は設計書のキーワードをもとにした **仮紹介文** です。
- 研究テーマカードの文章は、各ゼミ担当者が内容を確認して調整してください。
- 写真や動画は現在一切掲載していません。後から掲載許可済み素材を入れます。
- ゼミ頻度、住所、教員名、実績などの未確認情報は記載していません。

## 動作確認方法

1. `index.html` をブラウザで開く（静的ファイルなのでビルド不要）。
2. PC幅でHOMEのレイアウト・縦スクロール・リンクを確認する。
3. ブラウザの開発者ツールでスマホ幅（例：375px）にして表示を確認する。
4. ハンバーガーメニューが開閉し、Escキー・外側クリックで閉じることを確認する。
5. 制作予定ページのリンクを押して案内が出ることを確認する。
6. 開発者ツールのConsoleにエラーがないことを確認する。
7. 他担当のページ作成後は `data-planned` を削除しリンク先を確認する。
